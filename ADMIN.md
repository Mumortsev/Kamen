# Управление каталогом КаменьТорг23

Интерфейс адаптирован из `Mumortsev/Kurortnik24`: список материалов, категории, карточка товара с галереей и вариантами цены. Авторизация и серверные операции реализованы отдельно для Next.js. Данные и магазин Kurortnik не используются.

## Где что работает

- `/admin/` на рабочем Next.js — вход владельца, сохранение, загрузка, публикация.
- `/Kamen/admin/` на GitHub Pages — просмотр опубликованного каталога и предпросмотр карточек. Изменения отключены; никакие пароли не вшиваются в HTML.
- Vercel — стандартный Next.js с серверными API. Требуются PostgreSQL (рекомендуется Neon) и публичный Vercel Blob. Файловая система функций не используется для постоянных данных.
- Локально или на VPS можно использовать SQLite и постоянную папку `CATALOG_DATA_DIR`. Это режим разработки/самостоятельного размещения, не резервный способ записи на Vercel.

## Рабочий сервер Node.js и SQLite

Бесплатный некоммерческий тестовый стенд использует Vercel, Neon Free и Blob. Боевой запуск запланирован на Amvera: для него поддерживается обычный Node.js 24 с постоянным диском, SQLite и локальными фотографиями.

1. На сервере задать `SITE_URL` с HTTPS-доменом и `CATALOG_DATA_DIR` — абсолютный путь к постоянной папке вне `public`.
2. Не задавать `DATABASE_URL` и `BLOB_READ_WRITE_TOKEN`, если используется SQLite и локальное хранение фотографий.
3. Выполнить `npm ci`, `npm run admin:init`, `npm run admin:user -- owner`, `npm run build`, `npm start`.
4. Настроить HTTPS/reverse proxy и резервирование папки данных. При работе через свой proxy задать корректный `TRUST_PROXY_HOPS`.

Папка данных должна сохраняться между деплоями. Пользователь, запускающий приложение, должен иметь права записи в неё. Без отдельного рабочего сервера Pages предоставляет только просмотр панели.

## Бесплатный демонстрационный стенд Vercel

1. Импортировать `Mumortsev/Kamen` как отдельный Next.js-проект, Node.js 24, build command `npm run build`, без `STATIC_EXPORT` и `NEXT_PUBLIC_BASE_PATH`.
2. Подключить отдельную Neon PostgreSQL через Storage/Marketplace. В проекте должна появиться серверная переменная `DATABASE_URL`.
3. Подключить публичный Vercel Blob; нужна серверная `BLOB_READ_WRITE_TOKEN`.
4. `SITE_URL` — канонический домен рабочего сайта (для теста можно использовать домен проекта Vercel). `LEAD_WEBHOOK_URL` и `LEAD_WEBHOOK_TOKEN` — существующая настройка получателя заявок.
5. В доверенной локальной среде загрузить переменные подключения к этому проекту, затем выполнить:

```bash
npm ci
npm run admin:init
npm run admin:user -- owner
```

`admin:init` создаёт отдельные таблицы `kt_*` и импортирует 145 товаров и 224 варианта из каталога репозитория только при отсутствии данных. Повторный запуск не перезаписывает изменения владельца. Команда `admin:user` запрашивает пароль без отображения ввода (минимум 12 символов), хранит scrypt-хеш и отзывает прежние сеансы этого пользователя. Для автоматизированной настройки доступна серверная переменная `ADMIN_SETUP_PASSWORD`; не сохраняйте её в репозитории и удаляйте после настройки.

6. Пересобрать/развернуть приложение после подключения переменных. Открыть `/admin/` и войти.

Если на Vercel база ещё не подключена, публичный сайт показывает исходный каталог для первичного просмотра. Админка не имитирует успешное сохранение в непостоянную память.

## Как работает публикация

Редактор сохраняет **черновую редакцию** каталога. Статус товара:

- «К публикации» — войдёт в следующий опубликованный каталог, если есть активная категория.
- «Черновик» — доступен только владельцу.
- «Архив» — сохранён для восстановления, но не показывается посетителям.

После нажатия «Опубликовать» сервер атомарно выпускает общий снимок. Главная, каталог, категории, карточки и калькулятор используют этот снимок. Варианты, фотографии и порядок также входят в него. Если другая вкладка изменила ту же карточку, сохранение получает 409 вместо перезаписи чужой работы. URL сохранённого товара закреплён, название можно менять независимо.

Калькулятор показывает опубликованные товары с включённым участием в расчёте и единицами м²/кг. Единица, минимальный заказ, плотность и фасовка настраиваются в редакторе. Каталог с неизвестной единицей продажи не получает выдуманную цену за площадь. Пустой список материалов обрабатывается без возврата к исходному JSON.

Открытый калькулятор проверяет редакцию при возвращении в окно и каждые 30 секунд, пока вкладка видима. Сервер повторно рассчитывает выбранный товар при отправке заявки. При смене редакции или скрытии позиции возвращает 409 и просит пересчитать; старый текст не выдаётся за актуальное подтверждение цены.

## Фото

Фото выбираются с телефона или компьютера, главную можно назначить отдельно и менять порядок. Исходник до 10 МБ/25 Мп уменьшается в браузере до 1600 px перед отправкой, чтобы укладываться в лимит тела Vercel Functions. Сервер повторно проверяет и декодирует изображение, записывает WebP и превью 400 px. SVG и произвольные URL не принимаются. Публичные адреса Blob разрешены только для каталога `kamentorg/`.

Удаление фотографии из карточки не удаляет исходный файл физически: опубликованные снимки и резервные копии продолжают ссылаться на него. Старые фотографии не исчезают при новом деплое.

## Автообновление GitHub Pages

1. В **GitHub Actions variable** `CATALOG_EXPORT_URL` указать публичный endpoint рабочего сайта: `https://<project>.vercel.app/api/catalog`.
2. В **серверном окружении Vercel** задать `PAGES_GITHUB_TOKEN`: fine-grained GitHub token только для `Mumortsev/Kamen`, разрешение Actions write. В браузер токен не передаётся.
3. Один случайный `PAGES_CALLBACK_TOKEN` сохранить в серверном окружении Vercel и GitHub Actions secret с тем же именем.
4. При желании добавить GitHub Actions variable `ADMIN_URL=https://<project>.vercel.app/admin/` для окружения сборки Pages для ссылки на рабочую панель.

Публикация запускает `pages.yml` с номером редакции. Workflow скачивает и валидирует опубликованный снимок, строит все адреса товаров заново и развёртывает HTML. Номер устаревшего запроса отклоняется. Публичные фото Blob остаются по неизменяемым URL; локальные `/uploads/` копируются в экспорт. Без настройки источника обычный push продолжает публиковать сохранённый JSON репозитория.

Панель показывает состояния: автообновление не подключено, сборка запрошена, обновление завершено, ошибка. Если сборка упала до этапа deploy, подробный результат доступен в GitHub Actions; повторная публикация повторит запрос. Никакая неудача Pages не отменяет успешное обновление рабочего сайта.

## Резервирование и восстановление

В панели можно скачать JSON товаров/категорий и восстановить его в **черновик**. Рабочий сайт изменится только после проверки и публикации.

Для PostgreSQL включите резервирование у провайдера Neon. `npm run admin:backup` также сохраняет JSON каталога; фотографии остаются в Blob и не удаляются редактором. Полная копия пользователей/сессий и версия базы восстанавливаются средствами PostgreSQL, а не импортом каталога.

Для SQLite `npm run admin:backup` использует online backup базы и копирует неизменяемые фото. Для восстановления остановите сервер и замените содержимое `CATALOG_DATA_DIR` соответствующей копией. База содержит хеши паролей и сеансы; резервную копию нельзя размещать в `public` или коммитить.

## Проверки

- `npm test` — исходные тесты и тесты админки; PostgreSQL-адаптер исполняется на PostgreSQL-движке PGlite без облачных доступов.
- `npm run build` — рабочий Next.js/API для Vercel.
- `npm run build:pages` — HTML, включая интерфейс админки без серверных маршрутов.
- `node scripts/audit-admin.mjs` — полный браузерный сценарий на изолированном localhost. Скрипт отказывается изменять внешний сайт; тестовые доступы читает из временного файла вне репозитория.

Клиентская панель не хранит Telegram ID/токен как доказательство входа: используются HttpOnly cookie, серверные сессии, CSRF-проверка и ограничение попыток входа. Каждый API изменения проверяет доступ отдельно.

## Удаление во время демонстрации

Кнопка «Удалить товар» удаляет запись из редактируемого каталога после подтверждения. Сайт и калькулятор обновляются после общей публикации. Удалить категорию можно только после переноса или удаления её товаров; для временного исключения используйте переключатель видимости. Сохранённые фотографии физически не удаляются, чтобы резервные копии и предыдущая опубликованная редакция сохраняли ссылки.

На демонстрационном Vercel-проекте задаётся `DEMO_MODE=1`: страницы и robots закрывают индексацию. Это не меняет настройки будущего рабочего сайта Amvera.

## Первоначальная настройка Neon через HTTPS

Если доверенная среда разработки не может подключиться к PostgreSQL по TCP, используются команды `node scripts/admin-init.mjs --http` и `node scripts/admin-user.mjs demo --http`. Они работают только с Neon и выполняют тот же первоначальный импорт через официальный HTTPS-драйвер. Настройка пользователя выполняется одной SQL-транзакцией. Обычная работа сайта по-прежнему использует PostgreSQL-адаптер с транзакциями; HTTPS-режим не заменяет его.

Переменные подключения должны находиться в приватном `.env.local` или окружении процесса. Пароли, токены и файл доступа к демонстрации не коммитятся. Тестовый сайт — `https://kamen-green.vercel.app`; доступ клиента защищён входом самой админки, публичный сайт не требует аккаунта Vercel.
