# Управление КаменьТорг23

Рабочая панель: https://kamen-green.vercel.app/admin/ . Доступ передаётся отдельно.

## Работа владельца

1. Откройте «Товары» → «Добавить товар» или выберите существующий.
2. Введите название и описание, загрузите фото. Первое фото будет главным; порядок можно менять.
3. Укажите цену **за выбранную единицу**: м², кг, штуку или погонный метр. Ноль означает «Цена по запросу». Если единица неизвестна, выберите согласование с покупателем: товар останется в каталоге, но не будет давать вымышленный расчёт.
4. Варианты товара — отдельные толщина, размер или фракция со своей ценой. Их можно добавлять и удалять.
5. Выберите одну или несколько категорий. Для скрытия снимите «Показывать товар на сайте».
6. Нажмите **«Сохранить товар»**. На серверном сайте изменения сразу доступны в каталоге, карточке и калькуляторе. Отдельной публикации нет. Уже открытый калькулятор получает обновление при возвращении во вкладку и каждые 30 секунд; перед приёмом заявки сервер проверяет актуальность цен.

Адрес страницы создаётся автоматически из названия. Совпадения получают числовое окончание. Переименование сохраняет прежнюю ссылку.

В «Категориях» можно создать, изменить или скрыть категорию. Удаляется только пустая категория: сначала перенесите её товары. Скрытая категория скрывает товары, если у них нет другой открытой категории.

В «Заявках» видны контакты, комментарии и полный проверенный состав заказа. Заявки хранятся в базе; их можно отметить обработанными, вернуть в новые или удалить с подтверждением. Внешние уведомления необязательны: `LEAD_WEBHOOK_URL` и `LEAD_WEBHOOK_TOKEN` подключаются отдельно.

## Параметры расчёта

Минимальный заказ задаётся в единицах товара. «Только целыми упаковками» округляет заказ вверх до упаковки; цена по-прежнему указана за единицу внутри неё. Насыпную плотность для кг заполняйте только по данным материала: без подтверждённой плотности калькулятор принимает вес напрямую. Объёмная плотность цельного камня не заменяет насыпную.

## Размещение

- Next.js + PostgreSQL + Blob — рабочий сайт на Vercel; постоянные изменения хранятся вне файловой системы функций.
- SQLite + каталог загрузок — вариант для сервера с постоянным диском (например, Amvera). При переносе понадобится экспорт текущего каталога, перенос пользователей/заявок и сохранение доступа к фотографиям либо их перенос.
- GitHub Pages — статическая копия для показа. Записи в базу там нет; панель ведёт на рабочий адрес. Pages закрыт от индексации, чтобы не создавать ещё одну копию сайта в поиске. Его сборка содержит снимок каталога; непосредственные изменения владельца видны на рабочем домене.

Переменные: `DATABASE_URL`, `BLOB_READ_WRITE_TOKEN`, `SITE_URL`; для SQLite `CATALOG_DATA_DIR`. Не хранить секреты в репозитории. `npm run admin:init`; `npm run admin:user -- owner` с приватным вводом пароля. Для Neon из среды без TCP: `--http`. Флаг `--allow-simple` существует только у команды установки пользователя для явно согласованного тестового доступа; обычная установка требует 12 символов.

Сохранение использует транзакцию, версию товара и блокировку состояния каталога. Скрытие/удаление сразу исключает товар из публичных выборок. Изменившиеся цены требуют нового подтверждения расчёта, сумма заявки рассчитывается сервером.

Резервная копия SQLite: `npm run admin:backup`. PostgreSQL: резервное копирование средствами провайдера; перед массовым обновлением контента `scripts/refresh-content.mjs` сохраняет приватную копию текущего состояния. Скрипт меняет только совпадающие исходные описания и параметры, не затирая правки владельца.

Проверка сценария владельца: `scripts/audit-owner-flow.mjs`, по умолчанию только изолированный localhost. `--live` разрешает исключительно согласованный стенд; создаёт временные записи, проверяет путь от фото до заявки и очищает записи. Пароль передаётся через `OWNER_TEST_PASSWORD`, не выводится в отчёт.

## Фото сайта

Раздел «Фото сайта» управляет четырьмя изображениями направлений на главной и фотографиями работ. Можно заменить фото, добавить работы, изменить порядок, удалить снимок и заполнить его текстовое описание. Первые шесть работ показываются на главной, остальные — в портфолио. Сохранение обновляет обе страницы сразу. Фотографии товаров меняются в карточках товаров; Hero исключён из редактирования.

## Отправка заявок на почту

Получатель зафиксирован: **kamentorg23@mail.ru**. До подключения SMTP заявки сохраняются в разделе «Заявки», в нём виден статус письма. После настройки новые заявки автоматически отправляются почтой; для старых есть кнопка «Отправить на почту».

Vercel → проект kamen → Settings → Environment Variables:

- `SMTP_HOST`: `smtp.mail.ru` (либо сервер выбранного провайдера).
- `SMTP_PORT`: `465` для TLS или `587` для STARTTLS.
- `SMTP_USER`: адрес почты отправителя.
- `SMTP_PASSWORD`: отдельный пароль приложения/SMTP, добавить как секрет.
- `SMTP_FROM`: подтверждённый адрес отправителя; можно не задавать, тогда используется SMTP_USER.

После добавления переменных нужен Redeploy. Для Mail.ru владелец создаёт отдельный пароль приложения в настройках безопасности почты. Обычный пароль от ящика передавать разработчику не требуется. Письмо содержит контакты, комментарий и весь проверенный сервером расчёт. Ошибка почты не удаляет принятую заявку; статус виден в панели. Факт приёма SMTP-сервером не гарантирует попадания во «Входящие» вместо «Спама».

Кнопка MAX временно использует `https://max.ru/+79384085644`, как согласовано. Настоящую ссылку профиля можно позже заменить в `data/company.json` → `maxUrl`; номер отображается отдельно в `maxPhone`.
