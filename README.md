# КаменьТорг23

Next.js 16, React 19, TypeScript. Рабочий сайт: https://kamen-green.vercel.app . Панель: `/admin/`. Одна кодовая база также собирает HTML для GitHub Pages.

## Локально

```sh
npm ci
cp .env.example .env.local
npm run admin:init
npm run admin:user -- owner
npm run dev
```

На сервере нужны `SITE_URL` и постоянное хранилище. На Vercel используются `DATABASE_URL` (PostgreSQL) и `BLOB_READ_WRITE_TOKEN`. Без PostgreSQL локальный сервер работает с SQLite в `CATALOG_DATA_DIR`. SQLite не используется для постоянных данных функций Vercel.

```sh
npm test
npm run typecheck
npm run build
npm start
```

Node.js 24, порт `PORT` или 3000. Next.js обслуживает `/api/leads`, `/api/catalog` и защищённые `/api/admin/*`. Формы сохраняют заявки в базу. Webhook — необязательное дополнительное уведомление; его секрет остаётся на сервере.

## Владелец

[ADMIN.md](ADMIN.md) — товары, категории, фотографии, варианты, видимость и заявки. Адреса автоматические, сохранение сразу обновляет рабочий сайт. [CALCULATOR.md](CALCULATOR.md) — проект из нескольких позиций, все поддержанные единицы, упаковки, ограничения и проверка суммы на сервере.

## GitHub Pages

```sh
npm run build:pages
npm run preview:pages
```

`out/` содержит HTML/CSS/JS; не редактируется и не коммитится. Workflow `.github/workflows/pages.yml` проверяет проект и публикует сборку в https://mumortsev.github.io/Kamen/ . Pages использует снимок каталога и не записывает изменения; панель ведёт на рабочий сервер. Формы статической копии готовят письмо, если не настроен внешний endpoint. Pages закрыт от индексации.

При заданном `CATALOG_EXPORT_URL` сборка может получить актуальный публичный каталог. Изменения владельца на рабочем домене не требуют сборки. Автоматическое обновление снимка Pages — отдельная необязательная интеграция.

## Контент и поиск

145 исходных товаров, 224 варианта, 16 категорий, 196 фото портфолио. Исходные цены, фотографии, ID и ссылки сохранены. Описания товаров, категории и пять статей переработаны; неподтверждённые гарантии, лечебные и магические свойства не используются. Контакты и бизнес-факты остаются реальными. Детали источников и неясные условия — в [CONTENT_AUDIT.md](CONTENT_AUDIT.md).

Новый сайт имеет канонические ссылки своего домена, sitemap, метаданные и Product/Store JSON-LD. `SITE_URL` должен соответствовать фактическому адресу. Админка и API исключены из индексации. Уникальные формулировки сами по себе не гарантируют отдельные позиции: нужны индексация, полезные данные и продвижение. Подключение Яндекс Вебмастера, Search Console и аналитики требует аккаунтов владельца; доступов в проекте нет.

## Проверка полного сценария

`OWNER_TEST_PASSWORD` передаётся приватным окружением, затем `node scripts/audit-owner-flow.mjs`. По умолчанию проверяется изолированный localhost: мобильный вход, добавление категории/товара/фото, цены вариантов, калькулятор, сохранение проекта, реальная запись заявки в базу, скрытие и удаление. Временные записи очищаются. Для явно согласованного стенда предусмотрен `--live`; другие удалённые адреса запрещены.

Обновление интерфейса: зацикленная галерея товара (свайп/стрелки), фотографии сайта через админку, плавающие MAX и возврат наверх. Временная ссылка MAX содержит согласованный номер; её работоспособность не подтверждалась. Почтовая отправка подготовлена через SMTP, но до добавления доступа письма не отправляются. Инструкция — в ADMIN.md. Для коммитов с `[skip tests]` workflow пропускает тесты и отдельную проверку типов по запросу владельца; сборка для публикации выполняется как обычно.
