# КаменьТорг23 — Next.js + GitHub Pages

Один проект для рабочего сайта и статической HTML-демонстрации. Next.js 16, React 19, TypeScript. Дизайн и контент общие: отдельной ручной HTML-копии нет.

## Запуск

```sh
npm ci
npm run dev
```

## HTML для GitHub Pages

```sh
npm run build:pages
npm run preview:pages
```

Демонстрация: `http://localhost:3000/Kamen/`. Готовые HTML, CSS, JS и изображения находятся в `out/`. Папка генерируется, не редактируется и не коммитится. GitHub Actions устанавливает зависимости, проверяет типы, собирает Pages и публикует только `out/`.

`build:pages` задаёт `STATIC_EXPORT=1` и `NEXT_PUBLIC_BASE_PATH=/Kamen`. Для другого имени репозитория измените base path. Кнопки, каталог, фильтры, калькулятор и Canvas работают без Node.js на хостинге. Формы по умолчанию готовят письмо на реальную почту компании: открытие письма не выдаётся за отправленную заявку. Можно задать `NEXT_PUBLIC_LEAD_ENDPOINT` для внешнего API с разрешённым CORS.

## Рабочая сборка

```sh
cp .env.example .env.local
# Настроить SITE_URL и серверный LEAD_WEBHOOK_URL.
npm run build
npm start
```

Node.js 24, порт из `PORT` (по умолчанию 3000). Сервер обслуживает Next.js и `/api/leads`: валидирует имя, телефон, согласие и размер запроса, передаёт заявку в CRM/webhook с серверным токеном. На клиент токен не попадает. Без webhook сервер отвечает 503; форма показывает возможность отправить письмо или позвонить, а не ложное подтверждение.

Это готовность к размещению на Node-хостинге, **не факт подключения CRM или переключения настоящего домена**. Для платформ без собственного Node-сервера используйте внешний endpoint либо адаптируйте `/api/leads` в функцию платформы.

## Контент

- `data/company.json`: бренд, согласованный основной телефон, почта, адрес, география.
- `data/catalog.json`: 145 товаров, 16 категорий, тексты, условия, цены, реальные варианты и прежние URL.
- `data/portfolio.json`: 196 фотографий работ.
- `data/articles.json`: пять информационных статей с прежними адресами.
- `public/assets/imported/`: 810 локальных WebP-изображений каталога и портфолио.
- `CONTENT_AUDIT.md`: источники, расхождения и сведения для подтверждения владельцем.

Данные перенесены 15.11.2026 с публичного сайта и его каталожного API. Это снимок, не автоматическая синхронизация: изменение на старом сайте само не меняет новую версию. Наличие и актуальную цену партии подтверждает компания. При редактировании каталога сохраняйте ID, путь, единицу продажи и условия цены. Не подставляйте единицу, если она не опубликована.

## Архитектура

`app/page.tsx` и серверные компоненты формируют готовую разметку. `app/catalog` — поиск и каталог. `app/[...legacy]` генерирует страницы по прежним URL товаров и категорий, а также доставку, монтаж, контакты и портфолио. Старые продуктовые пути сохранены без клиентских перенаправлений. Отсутствующие пути возвращают 404.

Клиентский код ограничен Canvas, калькулятором, поиском и формой. В Canvas-движке нет React-обновлений на каждом кадре; модуль и манифест загружаются отдельно, слушатели и текстуры освобождаются при переходе. Фотографии подготовлены в WebP, шрифты — в WOFF2. Дополнительные отделки первого экрана загружаются по выбору.

`components/Calculator.tsx` использует опубликованные цены вариантов. Монтаж и доставка не выдаются за подтверждённые тарифы: в сумму входит материал, услуги рассчитываются отдельно. Для отсыпки плотность и округление упаковки явно обозначены как допущения.

Pages получает `noindex` и закрытый robots.txt, чтобы демонстрация не конкурировала со старым доменом. Рабочая сборка открыта для индексации, содержит sitemap и canonical. До запуска проверьте канонический домен, юридические сведения, аналитику и обработку заявок.

## Проверки

```sh
npm run typecheck
npm run build:pages
npm run build
```

Проверены мобильный и десктопный пути: сборка/разборка камня, выбор отделки, 145 товаров, поиск, старые URL, варианты цен, расчёт, передача в заявку, подготовка письма. Серверная доставка заявки проверена на локальном тестовом получателе; реальные письма и обращения в CRM владельца не отправлялись.

## Технический аудит

`TECHNICAL_AUDIT.md` — итог, исправления и ограничения проверки. Машиночитаемые результаты находятся в `audit/`.

- `npm test` — расчёт, валидация и серверная обработка заявок (без реальной CRM).
- `npm run audit:browser` — браузерные сценарии на локальной HTML-сборке, требуется Chromium (`CHROMIUM_PATH`, по умолчанию `/usr/bin/chromium`). Для WebKit задайте `WEBKIT_EXECUTABLE`; без него отчёт охватывает только Chromium.
- `npm run audit:a11y` — axe на главной, каталоге, карточке, калькуляторе, контактах и открытом меню.
- `node scripts/audit-production.mjs` — только локальный Node-сервер с тестовым получателем; реальные заявки владельцу не отправляет.

Для рабочей отправки API должен ответить JSON `{ "ok": true }`. HTML со статусом 200 и JSON без подтверждения не считаются успехом. Таймаут клиента — 15 секунд, получателя — 10 секунд. Клиент и сервер используют общую валидацию.

За доверенным reverse proxy настройте `TRUST_PROXY_HOPS` на действительное число доверенных узлов (обычно 1). По умолчанию 0: входящие `X-Forwarded-For` не принимаются за адрес посетителя. Не включайте доверие, если возможен прямой доступ к приложению мимо вашего прокси.

Статический обход всех HTML и внутренних ссылок: `python scripts/audit-static.py` после `build:pages` (нужен пакет `beautifulsoup4`). Замер кадров: `node scripts/audit-performance.mjs`. Lighthouse запускается отдельно, когда остальные браузерные проверки завершены; одиночная оценка не заменяет проверку на физическом устройстве.

## Админка и единый каталог

Интерфейс: `/admin/` на рабочем сайте, `/Kamen/admin/` в HTML-демонстрации.
Управление ценами, фото, описаниями и вариантами — через защищённую панель; публикация обновляет каталог и калькулятор одной редакцией.
Рабочая версия поддерживает Node.js с SQLite и постоянным хранением фото; облачные адаптеры необязательны. Настройка входа, импорта и автообновления Pages: [ADMIN.md](ADMIN.md).
